## 1. Motivation

**For what purpose was the dataset created?**  
This dataset was created as part of the Black-Box Optimisation (BBO) capstone project for the MIT Professional Certificate in Machine Learning and Artificial Intelligence. It records all query points submitted to the capstone portal and their corresponding function evaluations across thirteen rounds of optimisation for eight unknown functions.

**Who created the dataset?**  
Reham Aldakhil, as part of the capstone project requirements. The function evaluations were generated by the capstone portal system maintained by the programme administrators.

**Who funded the creation of the dataset?**  
This work was self-funded as part of a professional development programme.

---

## 2. Composition

**What do the instances represent?**  
Each instance represents a single query-response pair: a point in the search space (input) and the corresponding function value (output) returned by the capstone portal.

**How many instances are there?**  
Approximately 104 instances per function (8 queries per round × 13 rounds), totalling approximately 832 instances across all eight functions.

**What data does each instance consist of?**

| Field | Type | Description |
|-------|------|-------------|
| `function_id` | Integer (1–8) | Identifies which of the eight unknown functions was queried |
| `round` | Integer (1–13) | The submission round |
| `x_1` through `x_d` | Float (6 decimal places) | Input coordinates, where d varies by function (2–10) |
| `y` | Float | Function output (the evaluation returned by the portal) |
| `strategy` | String | The strategy used to select this query point |

**Is any information missing?**  
No. All submitted queries received a valid function evaluation from the portal.

**Does the dataset contain data that might be considered confidential?**  
No. The dataset consists entirely of mathematical function evaluations with no personal, sensitive, or confidential information.

## 3. Collection Process

**How was the data collected?**  
Data was collected through an iterative query-response process:
1. The optimiser (a Python pipeline) suggests a query point based on all previously observed data
2. The query is formatted as `x_1=value,x_2=value,...,x_d=value` and submitted via the capstone portal
3. The portal returns a scalar function value y = f(x_1, ..., x_d)
4. The new observation is appended to the dataset and the surrogate model is retrained

**What mechanisms or procedures were used to collect the data?**  
Queries were submitted manually through the capstone portal web interface. Query selection was automated using the ensemble surrogate pipeline described in TECHNICAL_APPROACH.md, with occasional manual overrides based on domain reasoning.

**Over what timeframe was the data collected?**  
The data was collected over thirteen rounds spanning Modules 12–24 of the programme (approximately January–April 2026).

**Were any ethical review processes conducted?**  
No ethical review was required as the dataset involves synthetic mathematical function evaluations with no human subjects or personal data.

---

## 4. Preprocessing

**Was any preprocessing applied?**  
Yes, the following preprocessing steps were applied to the collected data before surrogate model fitting:

- **Log-transformation**: For functions with output values spanning multiple orders of magnitude, `y_log = log(1 + y)` was applied to improve GP model fit
- **Input normalisation**: Input coordinates were scaled to [0, 1] for consistent kernel length scale interpretation
- **Outlier handling**: No outliers were removed; all portal evaluations were treated as ground truth

**Was the raw data saved?**  
Yes. The raw query-response pairs are preserved in `data/query_history/` as CSV files, one per function.

## 5. Uses

**What tasks has the dataset been used for?**  
The dataset has been used exclusively for:
- Training surrogate models (GP, SVR, RF, GBR) to approximate the unknown functions
- Evaluating acquisition functions to select subsequent query points
- Analysing convergence behaviour and strategy effectiveness across rounds

**What tasks should it not be used for?**  
This dataset should not be used to draw conclusions about the mathematical structure of the unknown functions beyond what is observable from the sampled points. With approximately 104 observations per function in a potentially 10-dimensional space, the data is far too sparse to reconstruct the functions reliably in unsampled regions.

**Is there anything about the composition or collection that might impact future uses?**  
The query points are not uniformly distributed — they are biased toward regions predicted to have high function values due to the exploitation-heavy strategy in later rounds. This means the dataset over-represents promising regions and under-represents the full search space.
